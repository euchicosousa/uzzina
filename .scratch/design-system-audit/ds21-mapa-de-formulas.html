Como cada cor do UZZINA nasce

Cada cor do app vem de uma fórmula escrita no CSS. Esta página mostra todas, com o número de cada conta e o resultado calculado agora pelo seu navegador, para a paleta e o modo que você escolher no topo. As amostras são desenhadas com o CSS real do app; o texto “com os números” é uma segunda conta feita em JavaScript, só para você conferir.

oklch(0.96 0.002 200)

Deslocamento de luz

É a mesma cor da origem, só um pouco mais clara ou mais escura. Matiz e intensidade ficam iguais. Não é mistura.

→L 0,93 C 0,03

Conta na própria cor

A cor sai de uma conta sobre outra cor: guarda o matiz da origem e fixa luminosidade e croma. Ninguém escreveu o valor final.

Mistura

Uma cor misturada com outra (o fundo, o cartão). Subgrupo Transparências: misturada com “nada”, então o resultado depende do que está atrás.

→
hover

Estado

Só aparece quando o mouse passa ou o campo ganha foco: cor do hover, sombra do hover, sombra do atraso.

Pontos de atenção

Coisas que parecem erro ou escolha sem explicação. Cada linha leva até o token. O status à direita muda com a paleta e o modo escolhidos.

Contraste do texto das fases

O texto do cartão de fase usa luminosidade fixa (0,35 no claro, 0,92 no escuro) sobre um fundo que muda com a cor da fase e da paleta. A razão é a medida WCAG calculada com as cores que o navegador resolveu agora. 4,5 ou mais passa para texto normal; entre 3 e 4,5 só serve para texto grande; abaixo de 3 reprova.

Fontes: tailwind.css (blocos :root e .dark, phase-surface, phase-vivid, late-surface), palettes.ts, palette-vars.ts, CONSTANTS.ts e button.tsx. Os valores de cada paleta entram do mesmo jeito que o applyPaletteVars aplica no app. As cores fora da gama sRGB aparecem recortadas no código hexadecimal.
