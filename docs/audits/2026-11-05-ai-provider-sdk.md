# SDK e rota de geração para OpenAI e Claude

Pesquisa documental em 05/11/2026. Disponibilidade pública, formatos documentados e comportamento da conta da CNVT são verificações distintas.

| Opção | Integração | Evidência de custo e uso |
| --- | --- | --- |
| Vercel AI SDK com provedores diretos | Usar `ai` com adaptadores explícitos. `@ai-sdk/anthropic` chama Messages com credencial Anthropic. Uma string de modelo no formato `criador/modelo` usa o Gateway por padrão. [Provedor Anthropic](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic) · [Provedor padrão](https://ai-sdk.dev/unauthenticated-ai-gateway) | `generateText` oferece uso por etapa, uso total, detalhes de cache e metadados. Conferir o payload nativo antes de depender da abstração para cobrança, especialmente quando há gravações com TTLs diferentes. [Contrato de generateText](https://ai-sdk.dev/docs/reference/ai-sdk-core/generate-text) |
| Vercel AI Gateway com o SDK OpenAI existente | Instanciar cliente separado com `baseURL: "https://ai-gateway.vercel.sh/v1"`, credencial Gateway e ID com prefixo. O catálogo público lista Haiku, Sonnet e Opus 5.5. [Integração com OpenAI SDK](https://vercel.com/academy/ai-gateway/existing-ai-stack) · [Haiku](https://vercel.com/ai-gateway/models/claude-haiku-5.5) · [Sonnet](https://vercel.com/ai-gateway/models/claude-sonnet-5.5) · [Opus](https://vercel.com/ai-gateway/models/claude-opus-5.5) | Guardar ID da geração e consultar `GET /v1/generation` para conciliar tokens, custo e provedor. No AI SDK, usar `providerMetadata.gateway.generationId` e `getGenerationInfo()`. Registrar custo calculado pela tarifa e débito do Gateway em campos conceitualmente separados. Validar respostas JSON dos comandos, o cache e a rota efetiva numa chamada controlada. [REST API](https://vercel.com/docs/ai-gateway/sdks-and-apis/rest-api) · [Implementação e documentação do Gateway no AI SDK](https://github.com/vercel/ai/blob/main/content/providers/01-ai-sdk-providers/00-ai-gateway.mdx) |
| Claude direto pela API Messages | Manter o cliente OpenAI atual e acrescentar Claude via `@anthropic-ai/sdk` ou um adaptador nativo de Messages. A camada de compatibilidade OpenAI da própria Anthropic rejeita `response_format: json_object`, usado em três fluxos atuais da UZZINA, e tem limitações de cache. [Messages TypeScript](https://platform.claude.com/docs/en/api/typescript/messages) · [Compatibilidade OpenAI da Anthropic](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk) | O uso nativo separa entrada sem cache, leitura e gravação, com detalhe de TTL quando reportado. A saída inclui thinking. A soma das três categorias de entrada dá a entrada total. O cálculo precisa preservar o ID retornado e a tarifa Anthropic aplicável à rota. [Messages TypeScript](https://platform.claude.com/docs/en/api/typescript/messages) · [Cache do Claude](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) |

A escolha depende do requisito de faturamento. Para cobrar pela conta direta e preservar a interpretação nativa de tokens, o menor recorte é manter OpenAI direto e integrar Claude via Messages no servidor. Se houver decisão de centralizar faturamento e conciliação na Vercel, o Gateway com o cliente atual é o experimento menor. Nessa rota, conferir a disponibilidade da conta, o provedor efetivo e o fallback. A Vercel documenta controles para restringir e ordenar provedores. Migrar todos os fluxos para o AI SDK é uma decisão de abstração separada. [Roteamento por provedor](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options) · [Gateway e faturamento](https://vercel.com/ai-gateway)

Na UZZINA, manter validação Zod, cotas e worker no servidor. Antes de liberar seleção de Claude, validar um comando JSON com a rota escolhida e comparar modelo real, tokens, cache, tarifa, custo e ID. Cobrir também resposta sem uso e retry só de gravação. A conciliação local deve distinguir custo calculado, custo reportado e custo pendente.

## Referência “OpenAI 2”

A expressão não resolve um identificador de modelo textual nem define se o assunto é uma versão de SDK ou endpoint. O catálogo oficial lista os GPT-6 usados para texto e o GPT-Image-2 (`gpt-image-2`) para imagens. Se a referência era ao GPT-Image-2, o escopo é geração/edição de imagem e o endpoint e a tarifação são próprios. Confirmar o nome ou link exato antes de incluir a referência no catálogo da UZZINA. [Catálogo oficial](https://developers.openai.com/api/docs/models/all) · [GPT-Image-2](https://developers.openai.com/api/docs/models/gpt-image-2)
